Payroll Management with ML forecasting

An HR backend that automates monthly payroll for 200 employees, keeps admins and employees in their own lanes, and forecasts what payroll will cost next.

View code ↗
42REST endpoints
200employees on automated payroll
4pay components · PF, tax, insurance, OT
2roles · JWT + bcrypt

The problem

Payroll is rules-heavy and unforgiving. Provident fund, slab-based income tax, insurance and overtime all change the number, and one wrong calculation reaches someone's bank account.

What I built

  • A Flask REST API with 42 endpoints covering employees, payroll, attendance and leave.
  • Auth with JWT and bcrypt, plus admin and employee roles so each user only reaches their own routes.
  • A payroll engine that runs PF, slab tax, insurance and overtime for 200 seeded employees and generates PDF payslips.
  • A Chart.js dashboard with Linear Regression cost forecasts.
  • pytest unit tests on payroll and anomaly logic, all packaged in Docker.

Architecture

Client→Flask API · JWT→SQLAlchemy→Payroll engine→PDF payslips+Scikit-Learn forecast→Chart.js

Decisions I'd defend

Tests on the money logic first. Tax slabs and PF are where silent bugs hide, so that's where pytest went.

Roles enforced in the API, not the UI. Hiding a button doesn't stop an employee from calling an admin route.

    Hybrid Malware Detection via memory forensics

    Upload a Windows memory dump and get a malicious-or-benign verdict for every running process, with the forensic evidence behind it.

    View code ↗
    3Volatility 3 plugins · pslist, pstree, cmdline
    1verdict per process
    2services · FastAPI + Next.js
    MLPKeras classifier

    The problem

    Some malware never touches the disk and only lives in RAM. A memory dump captures it, but reading raw Volatility output by hand is slow and needs an expert.

    What I built

    • A FastAPI service that accepts a Windows memory dump and runs Volatility 3 plugins on it.
    • A parser that turns plugin output into per-process features.
    • A Keras MLP that labels each process malicious or benign.
    • A Next.js + TypeScript dashboard to upload dumps and review results.

    Pipeline

    memdump.raw→FastAPI→Volatility 3→Feature parser→Keras MLP→Next.js dashboard

    Decisions I'd defend

    Score processes, not whole dumps. An analyst needs to know which process to look at, not just that something is wrong.

    Forensics and ML as separate services. Volatility runs slow and heavy, so the API owns it and the UI stays fast.

    Traffic Sign Classification
    
            
    A CNN that reads German road signs at 96.8% accuracy and says "I'm not sure" instead of guessing when the photo is bad.
    
          
    
          
    View code ↗
    
        
    
        
    
          
    96.8%test accuracy
    
          
    0.95macro-F1
    
          
    43classes · GTSRB
    
          
    9,952held-out test images
    
        
    
        
    
          
    
            
    The problem
    A classifier always outputs some answer, even for a blurry or unfamiliar sign. For road signs, a confident wrong answer is worse than no answer.
    
            
    What I built
    
              
      
                
    • A 3-block CNN with batch normalization and data augmentation, trained on GTSRB.
      • 
                
    • 96.8% accuracy and 0.95 macro-F1 on 9,952 held-out images, so rare classes hold up too.
      • 
                
    • A Flask web app: upload a photo, get a prediction.
      • 
                
    • A 60% confidence gate that rejects low-confidence predictions instead of guessing.
      • 
              
    
            
    
            
    Inference path
    
              
    Image upload→Flask→Preprocess→CNN · 43-way softmax→≥ 60%?→Label / reject
    
            
    
            
    Decisions I'd defend
    
              
    Report macro-F1 next to accuracy. With 43 imbalanced classes, accuracy alone can hide a class the model never gets right.
    
              
    Refuse below 60%. Asking for a clearer photo costs a second. A wrong sign costs a lot more.
